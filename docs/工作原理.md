# 工作原理

实现细节说明。README 中仅保留结论。

## 一、为什么普通 mod 包放不进去

游戏会校验每个资源容器（`.pak`）的数字签名，**未签名**的容器直接被拒绝加载。
所以把自制的 `pak` 丢进 `Game\Content\Paks\` 不会生效，游戏当它不存在。

绕过方式有两条：修改可执行文件，或在进程内插入钩子。本工具采用后者。

## 二、代理 DLL

本工具装入的 `dinput8.dll` 在游戏进程启动的**最早期**挂钩 `FPakFile` 构造函数入口，
对名称形如 `pakchunk0-Windows_<任意>_P.pak` 的**补丁包**强制跳过签名校验。
**官方容器完全不受影响**，仍走原有校验路径。

### 为什么是 `dinput8.dll` 这个名字

游戏静态导入 `DINPUT8.dll`，Windows 在加载 exe 导入表时即加载该文件。
这是最早的用户态执行时机，可在所有容器挂载之前完成挂钩。

可执行文件所在目录的同名 DLL 优先于系统目录中的同名文件被加载，代理机制即基于此。

### 依赖

- 只依赖 `kernel32`，不含任何第三方二进制
- 不依赖 MinGW / CRT 运行时（静态链接，`-nostdlib` 风格的最小 PE）
- 实现：`src/proxy/ac8proxy.c`（钩子安装 + 包名匹配）+ `src/proxy/ac8hook.s`（手写汇编跳板，
  精确还原 `rsp`）

### 包名规则

放行规则是**通配**而不是写死某一个名字：

```
pakchunk0-Windows_<任意数字>_P.pak
```

因此可以与使用其它编号的补丁包（例如 `..._999_P.pak`）的 mod 共存。
规则由 `src/proxy/selftest.py` 从 `ac8proxy.c` 中**抽取真实函数**生成测试程序验证，
共 15 个用例，覆盖「自己的包被放行」「官方容器不被误伤」两侧。

> 注意：包名规则自测通过，但**游戏内与其它 mod 同时挂载未做完整实测**。

### 版本适配

代理 DLL 会先比对游戏可执行文件的指纹。指纹不符（游戏更新了）时**主动放弃挂钩**，
管理器状态显示「游戏版本 **未适配**」。这是保护机制：强行挂钩到未知二进制可能导致崩溃。

## 三、更新清单 `dist/version.json`

这份清单既是**远程清单**（管理器从 GitHub 读），也是 `payload\` 里的**本地版本标记**。

```json
{
  "version": "2026.10.19.2",
  "tag": "v2026.10.19.2",
  "released_at": "2026-10-19T13:40:33Z",
  "notes": "更新说明（纯文本，可含换行）",
  "files": [
    { "name": "pakchunk0-Windows_998_P.pak", "size": 569876, "sha256": "…" },
    { "name": "dinput8.dll",                 "size": 8192,   "sha256": "…" }
  ]
}
```

### 检查更新的流程

实现见 `src/gui/main.c`：

1. 调 `api.github.com/.../releases/latest` 取**最新 tag**
   （不直接读 `main` 分支的清单，因 raw 地址存在 3 至 5 分钟 CDN 缓存，发布后短时间内仍会返回上一版）
2. 按该 tag 读 `dist/version.json`（tag 指向的内容不可变，不会有缓存漂移）
3. 与本机 `payload\version.json` 的 `version` **逐段数值比较**：
   - 相等 → 「已是最新」
   - 线上更新 → 提示更新
   - 本机更新 → 不提示，**不引导降级**
4. 有新版时从 `…/<tag>/dist/<文件名>` 下载
5. 校验 `size` + `sha256`，全部通过才替换 `payload\`；
   若汉化已启用，同时更新游戏目录里的文件（旧文件进 `_backup\`）

**中途任何一步失败都不动现有文件。** 管理器启动时自动查一次（只有发现新版才提示），
也可以随时手动触发。命令行等价物：`check` / `update`。

## 四、目录结构

```
├── dist/            译文包、代理 DLL、更新清单
│   ├── pakchunk0-Windows_998_P.pak
│   ├── dinput8.dll
│   └── version.json
├── src/
│   ├── gui/          管理器（Win32 GUI，单文件 C）
│   │   ├── main.c
│   │   ├── app.rc / app.manifest   视觉样式 + 免提权清单
│   │   └── build.sh
│   └── proxy/        代理 DLL
│       ├── ac8proxy.c    钩子安装 + 包名匹配
│       ├── ac8hook.s     汇编跳板
│       ├── win32_min.h / k32.def
│       ├── selftest.py   包名匹配自测
│       └── build.sh
└── docs/
    └── 使用说明.txt   随发布包一起分发的简版说明
```

## 五、译文来源

译文包 `pakchunk0-Windows_998_P.pak` 内只含两个文件：`CP_M.dat` 与 `ON_M.dat`，
即官方数据文件的完整替换版本。未修改的条目保留官方原文，仅替换译文条目。

译文在独立的翻译工作区中维护，本仓库只发布打包产物。
